# 문제 정의서: 체성분 결과지 → 운동 루틴 추천 PoC

- 과정: AI Agent 서비스 개발자 과정, Main Quest 2
- 작성일: 2026-11-17
- 상태: 초안

## 1. 도메인

**나만의 헬스도감** (Main Quest 1, https://ai-agent-mainquest1-health.vercel.app)
헬스 입문자가 기구별 운동 자세·자극 부위를 찾고, 운동하고 싶은 부위에 맞는 기구를 찾는 모바일 웹 도감이다. 대표 기구 20개, 즐겨찾기, 운동 기록 기능이 있다.

이번 PoC는 이 도감에 **"내 체성분 결과지로 운동 루틴 추천받기"** 기능을 붙일 수 있는지 검증한다.

## 2. 대상 사용자

| 사용자 | 상황 |
|---|---|
| 나 (개발자 본인) | 헬스장에서 체성분 검사를 받지만, 결과지를 보고 무엇을 바꿔야 할지 매번 따로 찾아본다 |
| 헬스 입문자 | 헬스장 등록 때 체성분 검사를 받고 결과지를 받지만, 숫자의 의미를 모르고 어떤 기구로 운동해야 할지 모른다 |

## 3. 현재 문제

1. **결과지를 해석하기 어렵다.** 골격근량, 체지방률, 복부지방률 같은 수치가 한 장에 수십 개 있고, 표준 범위 숫자까지 섞여 있어 입문자는 무엇이 중요한지 모른다.
2. **수치를 옮겨 적는 데 시간이 든다.** 앱이나 메모에 핵심 수치 8개를 손으로 입력하면 약 2분이 걸리고 오타가 생긴다.
3. **결과지와 운동이 연결되지 않는다.** "체지방률이 높다"는 걸 알아도, 헬스장에 있는 어떤 기구로 무엇을 해야 하는지까지 이어지지 않는다.
4. **일반 챗봇의 추천은 내 환경과 맞지 않는다.** ChatGPT 같은 범용 챗봇에 물어보면 헬스장에 없는 기구나 도감에 설명이 없는 운동을 추천해서, 자세를 확인할 수 없다.

## 4. 개선 가설

> 결과지 사진 한 장으로 핵심 수치를 자동 추출하고, **헬스도감에 있는 운동만으로** 루틴을 구성해 주면, 입력 시간은 2분에서 10초 이내로 줄고 추천된 모든 운동을 도감에서 바로 자세까지 확인할 수 있다.

## 5. 해결 방식 (파이프라인)

```
결과지 사진
  → ① 수치 추출 (OCR+정규식 / Gemini Flash / Claude 비전 비교)
  → ② 수치 JSON (8개 핵심 필드)
  → ③ 루틴 추천 (도감 운동 목록 + 수치 → LLM → 구조화된 JSON)
     → 도감에 없는 운동은 코드에서 한 번 더 제거
  → ④ 헬스도감 화면에 표시 (운동마다 도감 상세로 연결)
```

### 추출할 핵심 8개 필드

| 필드 | 키 | 단위 |
|---|---|---|
| 체중 | `weight_kg` | kg |
| 골격근량 | `skeletal_muscle_kg` | kg |
| 체지방량 | `body_fat_kg` | kg |
| 체지방률 | `body_fat_pct` | % |
| BMI | `bmi` | kg/m² |
| 기초대사량 | `bmr_kcal` | kcal |
| 체성분 점수 | `score` | 점 |
| 복부지방률 | `whr` | (비율) |

## 6. 데이터

- **실제 결과지는 쓰지 않는다.** 체성분 결과는 개인 건강정보라서, 본인 것이라도 공개 저장소에 올리지 않는다.
- 대신 **가상 체성분 결과지 이미지 + 정답 JSON**을 직접 생성한다.
  - 특정 브랜드의 로고·양식을 그대로 베끼지 않고, 일반적인 결과지 구성(체성분 표, 막대그래프, 표준 범위, 점수)을 흉내 낸 자체 양식을 쓴다.
  - 표준 범위 숫자 같은 **헷갈리는 숫자**를 일부러 넣어, 실제 결과지처럼 "어떤 숫자가 측정값인지" 구분해야 하게 만든다.
  - 일부 이미지에는 기울기, 흐림, 그림자, 저해상도를 넣어 폰 촬영을 흉내 낸다.

## 7. 성공 기준

| 항목 | 기존 방식 | 목표 |
|---|---|---|
| 핵심 8개 필드 추출 정확도 | 수기 입력 (오타 가능) | **95% 이상** (전체 필드 기준) |
| 입력 시간 | 약 2분 (수기) | **10초 이내** (사진 → 수치) |
| 추천 운동의 도감 포함률 | 범용 챗봇: 도감 밖 운동 포함 | **100%** (도감 안 운동만) |
| 흐린·기울어진 사진 | - | 깨끗한 사진 대비 정확도 하락 폭을 측정해 기록 |

## 8. 범위

**이번 PoC에 포함**
- 모델 3종 비교 (정확도, 장당 처리 시간, 비용, 촬영 상태별 성능) → 모델 선정 근거
- 도감 운동 제약 루틴 추천과 도감 밖 운동 필터링
- 재현 가능한 노트북 (Colab), 가상 데이터 생성기, 검증 문서, 실패 사례

**포함하지 않음**
- 실제 결과지 대량 검증 (개인정보 문제로 다음 단계)
- 브랜드·기종별 양식 대응
- 의료적 판단·진단 (추천 결과는 의료 조언이 아니라는 고지를 함께 표시)

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 가상 결과지는 실제와 다를 수 있다 | 헷갈리는 숫자와 촬영 노이즈를 넣어 난이도를 높이고, 한계로 명시한다 |
| LLM이 도감에 없는 운동을 만들어 낸다 | 프롬프트에 운동 ID 목록을 주고 JSON 스키마로 받은 뒤, 코드에서 ID를 다시 검사해 제거한다 |
| API 키 노출 | 키는 노트북 비밀값(Colab Secrets)이나 서버 환경변수로만 다루고 저장소에 올리지 않는다 |
| 건강 관련 오해 | 화면과 문서에 "의료 조언이 아니다" 고지 |
